## Training decisions

1. A from-scratch run fit a new vocabulary on the 529 training pages. Its
   best checkpoint was epoch 5 of 30. On validation, article exact accuracy
   fell from 71.6% to 51.6%, and authors fell from 58.4% to 50.0%. It was
   rejected.
2. A warm-start run reused the current checkpoint's vocabulary, normalizer,
   and weights, then trained on the 529-page training split at learning rate
   `0.0001` for 15 epochs (seed 17). Epoch 15 had the lowest validation loss,
   `1.3512`. It is the candidate in this PR. Its source checkpoint SHA-256 is
   `df0b2855f23dc75b6956ae47c0577661e8c22d4f72538e82dc2187296e88f788`.
3. I trained author-boundary refiners for the new base checkpoints. The
   warm-start refiner made zero validation and test changes at its selected
   margin, so it is not needed with the candidate. A refiner trained against
   the old base improved four validation pages but remained below the existing
   bundled refiner. Neither new refiner was promoted.

## Exact-node accuracy

Each value is the share of pages where the predicted DOM node ID equals the
human-reviewed node ID. Missing predictions count as correct only when the
human label is also missing. The **present authors** column excludes pages
whose human author label is missing.

| Split / checkpoint | Article | Title | Authors | Present authors | Date |
| --- | ---: | ---: | ---: | ---: | ---: |
| Validation, current default | 71.6% | 95.2% | **58.4%** | **59.7%** | 89.6% |
| Validation, new candidate | **72.4%** | 95.2% | 51.6% | 52.5% | **92.0%** |
| Test, current default | 87.3% | 80.7% | 34.0% | 34.1% | 80.7% |
| Test, new candidate | 87.3% | **81.3%** | **43.3%** | **42.2%** | **84.7%** |

Validation has 250 pages, including 50 new pages. Test has 150 pages,
including 120 new pages. The original 30 test pages have been inspected during
earlier development, so the entire 150-page set is not a pristine external
benchmark. The candidate's test improvement is encouraging but conflicts with
the validation author regression. Keep the default until a new run improves
validation without that regression, then evaluate test once.

## Reproduce locally

This requires the ignored `data/learned_extraction/raw` dataset with its
human-reviewed annotations. Run the split preview first, then apply it. The
apply command saves the old manifest before replacing it.

```bash
uv run python -m modeling.dom_extractor.commands.rebalance_reviewed_corpus
uv run python -m modeling.dom_extractor.commands.rebalance_reviewed_corpus --apply
uv run python -m modeling.dom_extractor.commands.prepare_dataset \
  --dataset-dir data/learned_extraction/raw \
  --output-dir data/learned_extraction/prepared_warmstart_20260925 \
  --preprocessing-checkpoint eng_universe/extraction/checkpoints/best.pt
uv run python -m modeling.dom_extractor.training \
  --prepared-dir data/learned_extraction/prepared_warmstart_20260925 \
  --output-dir data/learned_extraction/model_warmstart_20260925 \
  --initial-checkpoint eng_universe/extraction/checkpoints/best.pt \
  --learning-rate 0.0001 --epochs 15
```

Use `score_reviewed_corpus` with `--split validation` to compare checkpoint
choices. Its default is the bundled two-model runtime; passing `--checkpoint`
uses the candidate base model without an author refiner. Only run
`--split test` after choosing the checkpoint on validation.

```bash
uv run python -m modeling.dom_extractor.commands.score_reviewed_corpus --split validation
uv run python -m modeling.dom_extractor.commands.score_reviewed_corpus \
  --split validation \
  --checkpoint modeling/dom_extractor/checkpoints/reviewed-2026-09-25-warmstart.pt
```
