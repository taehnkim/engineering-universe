Integrated AI Architectures for Superhuman Accuracy

Leveraging Both Specialized CV Models and Foundation VLMs for Blueprint Analysis

We productionized a state-of-the-art blueprint analysis system that leverages both small, task-specific computer vision models and large multi-modal foundation models in conjunction. Specialized CV models excel at precise element detection and measurement extraction, but struggle with extracting and reasoning about text. Conversely, while large foundation models excel at extracting and reasoning about text written on drawings and are able to perform less-constrained tasks, they struggle with precise element detection and often hallucinate when presented with too much visual information. Our integrated approach achieves 96.8% overall accuracy across all information we extract from the plans by combining precise element extraction from small, task-specific models with the textual understanding and reasoning ability of large foundation models.

Example: Parapet Height Extraction

What are parapets?

Parapets are railings on the edge of roofs. They are typically required on accessible roofs for the safety of those on the roof.

How are parapets represented on plans?

Each color represents a single parapet. We know that there is a parapet because there is a “TOP” (top of parapet) marker on each side for which I drew a line. As you can see, for homes with accessible roofs, there are a lot of different parapets on the roof. However, most of these parapets are not on accessible segments of the roof, and are thus not relevant to extract. Specifically:

  • The green and pink parapets on the roof of the “penthouse” (structure which occupies a fraction of the top floor of the home) is never accessible
  • The orange parapet encompasses the accessible part of the roof and thus we need to measure the heights of the parapets on these sides. We can determine that this part of the roof is accessible because there are boundaries drawn separating this part of the roof on the plan with those of other parts of the roof, there is text denoting that this is the roof of the first floor of the building and not the penthouse, and the finished floor level (denoted by the FFL marker) is lower than that of the penthouse roof.

Note: The true height of the orange parapet is 1.05m, which is less than the minimum required height of 1.2m! We can determine this by reading the height of the finished floor level by observing the FFL marker (7.38m) and subtracting that from the top of parapet (TOP) height (8.43m)

An engineer analyzing a commercial building floor plan needs to be able to extract the exact measurements of the top and floor of a parapet, while simultaneously understanding spatial relationships and design intent (which roof areas are accessible roof space).

Potential Approaches

There are several approaches one can take to extracting the height of the parapet surrounding the accessible segment of the roof.

Naive Foundation Model Usage

The obvious one that comes to mind is naively using a state of the art large foundation model to achieve this. That would look something like this

We’ve evaluated this approach on hundreds of documents and found that multimodal foundation models, even state of the art models like GPT-5 and Gemini 2.5 Pro, struggle with this task and often return the height of the wrong parapet. Empirically, we found accuracy to be 60% when using only a foundation model because:

  1. Foundation models still struggle a lot with visual understanding. Their proficiency with textual understanding and reasoning is much higher than their proficiency with visual understanding and reasoning
  2. This is a complex task where the model is being asked to discriminate between a lot of parapets and only return the height of the “correct” one, and the definition of correct is only encoded in the our prompt
  3. There is a lot of context about analyzing architectural drawings that the model likely missed during training. We can pass some of that context in our prompt, but given the complexity of the task there is only so much it can learn

Train a Task-specific Model

Another approach we considered is to train a small, task-specific computer vision model for this task end to end. Specifically, this model would take an image as input and directly output a number corresponding to the smallest height of the parapet on the accessible roof of the villa. To do this, we would have to do the following:

  1. Build a dataset where, for each architectural drawing, we would have an annotation for the minimum parapet height of the accessible roof of the villa
  2. Determine which model architecture to use and train a model to perform this task end to end

However, this approach would have the following challenges:

  1. Due to its complexity, annotation for this task is both tricky and time-consuming. We tried this with a third party annotation team that we worked with, and it required several iteration cycles. Ultimately, it would’ve taken at least a few weeks to get a high-enough quality dataset to train this model
  2. As a space, using task-specific computer vision models for regression problems is under-explored compared to using task-specific computer vision models for localization and classification problems. As such, to pursue this we would likely need to do some research in model architectures. This is very time consuming and likely would take months of experimentation to get right

Due to these challenges, we decided to exhaust all other possible strategies before attempting this one.

Integrated Approach

The approach we’ve ultimately found to be the most performant and thus deployed to production is to combine the strengths of task-specific computer vision models and foundation models.

Production Deployment Insights

The solution we built does not require our ML stack to run in real time. This greatly simplifies our production serving stack, but there is still some complexity in how we serve model inference requests:

  • Our software stack is completely deployed in the cloud
  • We have one “main” node which orchestrates all of the model inference requests. This service is deployed on a light CPU cloud node and is deployed as a docker containerized microservice with kubernetes autoscaling
  • We have another node that we host for our ML models. These are also deployed as docker containerized microservices with kubernetes autoscaling, but they are deployed on GPU cloud nodes
  • We also leverage third party APIs to make foundation model inference requests. These are called from our main cloud node

  • We used a third party annotation service to annotate our images with a combination of object detection and instance segmentation annotations.

Results

By leveraging each class of models for their strengths and using them in a complementary fashion to address their weaknesses, we were able to achieve 97% accuracy on determining whether each attribute of a plan was compliant with building codes compared with only ~60% accuracy with the Naive approach.

Architectural blueprint analysis represents a broader challenge in technical document understanding: pixel-level precision requirements, visual spatial reasoning, and contextual interpretation capabilities. Our systematic evaluation reveals that different AI approaches excel at fundamentally different aspects of this challenge.

Key Technical Insights:

  1. Task-dependent performance optimization is crucial
  2. Integrated architectures achieve superior performance

The result is a framework for intelligent blueprint analysis that routes tasks to optimal AI approaches based on extraction requirements, delivering both the precision needed for quantitative analysis and the contextual understanding required for qualitative assessment.
